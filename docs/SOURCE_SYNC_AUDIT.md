## 历史审计与公开风险

原本地 12 个提交、168 个唯一文件对象已检查，未发现高置信私钥、数据库、证书包或 API Token。但初始提交即包含真实经营数据：旧导入核对/需求文档有设备 SN、单据编号、采购成本、售价和金额汇总。远端当前 main 快照也保留相同资料。

因此新分支采用**无父提交的独立根分支**，不继承旧文档历史；原 main 及其历史不删除、不重写。对旧文档中提取的 6 个完整真实 SN、14 个完整单据编号进行内存精确比对，新候选文件未命中。

**新分支净化不等于原仓库可以安全公开。** GitHub 可见性影响整个仓库，公开会一并公开旧 main 及历史。单纯删除当前文件、修改 `.gitignore` 或创建干净分支都无法消除旧提交内容。

2026-11-01 公开后已只读获取远端 main 的全部 39 次提交，逐一检查 136 个唯一文件对象（1,013,946 字节）。未发现数据库、真实 `.env`、私钥或证书文件；高置信凭据模式扫描未检出泄露，75 个本地私有凭据候选在内存精确比对亦为零命中。与此前本地历史相比，远端仅新增空 `favicon.svg` 与旧 `sync-manifest.json` 两个文件对象，没有发现额外内容风险。

旧真实经营资料依然存在于远端 main 当前文件及历史，首次引入提交为 `de85ad22b941c4fd994baa2aec2ac541940d72e4`。这是已发现且用户明确接受的风险，不能将原仓库描述为“已脱敏”。扫描覆盖已获取的 main 完整历史及本次准备分支，不对未获取的 ref、外部附件或任何未识别内容作绝对无风险保证。
