# 服务端使用说明（v0.5 联机测试版）

## 本机运行

Node.js 24.13+，在项目根目录执行 `npm start`。默认访问 http://127.0.0.1:4318/ ，首次建立老板账号。账号为 3–40 位字母、数字、点、横线或下划线，密码为 12–128 位。

首次选择空白测试账或演示测试账。空白测试账不预置收付款账户。老板在“账户管理”中新增实际账户、类型、启用日期与期初余额；期初余额不计利润或老板垫款。账户可编辑名称和类型，历史流水保持原关联。新建客户、供应商与商品后，可以登记老板垫入、上游预付、直接采购入库、销售和回款。

老板可管理成员、新增和编辑收付款账户、关账和反关账。财务录入直接生效。关账后所有人员均不能直接写入该月份，老板必须填写原因并反关账。

代码更新后请重启后台。若多个终端中存在旧后台，可双击 `scripts/重启本地测试后台.command`：仅停止本项目占用 4318 的 Node 服务，再启动新版，保留账本。

## 供应商应付

新采购直接登记入库，不再提供登记锁货入口。入库时可选择使用供应商预付款，或记应付之后付款／明确抵扣；可选填上游发货日期。旧采购单仍可继续确认发货及入库，避免历史数据失联。采购快递费计入库存成本，不混入供应商货款。

同一供应商的可用预付款、待付货款分别显示。财务从指定应付单选择“登记付款”，扣减所选银行账户并减少应付；或选择“用预付款抵扣”，只减少该供应商预付和指定应付，不产生银行流水。支持部分结清，不允许超付、超余额或早于收货。为避免倒用后来的余额，涉及已有后续预付/抵扣的倒序操作会被拒绝。

已有账本无需 SQL 迁移；缺失的应付集合按空集合处理。期初供应商预付款及应付可在期初建档中分别填写。

## 运行配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4318` | 服务端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `APP_ORIGIN` | `http://127.0.0.1:4318` | 允许的网站来源，必须与浏览器及 Host 头一致 |
| `DB_PATH` | `data/finance.sqlite` | 数据库路径，建议使用绝对路径 |
| `TRUST_PROXY_IP` | 空（不信任转发头） | 仅信任此单一 TCP 来源提供的 `X-Finance-Client-IP`；生产 Compose 使用固定 Caddy 地址 |

独立测试账示例：

```sh
PORT=4319 DB_PATH=data/another-test.sqlite node server/start.mjs
```

网页只读写服务端账本，不将业务账本存入 localStorage。断网或服务停止时不能本地记账。保存发生网络中断时，应保留表单原内容并重试：同一提交标识不会重复入账。未确认结果时页面会阻止关闭表单并提示离开；不要强制关闭后重新手录，先核对账本。

如果出现「账本已被其他操作更新」，页面读取最新数据，核对后再保存。打开的表单不受定时刷新覆盖；关闭表单时每 30 秒以及窗口重新获得焦点时刷新。

## 账号与权限

- 密码以带随机盐的 scrypt 哈希保存，无默认密码。
- 会话有效期 8 小时，HttpOnly、SameSite=Strict cookie；HTTPS 下额外使用 Secure。
- 来源、CSRF、角色和账期由服务端校验；登录失败限流。
- 默认直连时忽略所有转发头。配置 `TRUST_PROXY_IP` 后，仅该精确来源可提供单一合法客户端 IP；受信代理缺失／重复／非法头或非受信连接伪造专用头均返回 403。登录按规范化客户端 IP 和账号分别限流，Caddy 必须覆盖专用头。
- 修改密码撤销该账号旧会话；停用或重置成员密码也撤销其会话。
- 老板不能停用自己，初始化仅开放在本机来源。
- 一个部署对应一家公司一本账。当前没有 MFA、自助找回密码、历史单据更正或审批工作流。审计保存在同一数据库，不能替代文件访问控制和独立备份。

## 备份与恢复

在线备份使用 SQLite 备份接口，不直接复制正在运行的 WAL 数据库：

```sh
node server/backup.mjs backup data/finance.sqlite backups/finance-2026-10-16.sqlite
```

备份含业务、账号哈希和会话信息，由管理员保管，不上传代码仓库。命令拒绝覆盖已有文件。

恢复会检查完整性和版本，生成新数据库并清空旧会话，成员需重新登录：

```sh
node server/backup.mjs restore backups/finance-2026-10-16.sqlite data/restored-2026-10-16.sqlite
```

停止服务，用新的 `DB_PATH` 启动并核对后使用。恢复不覆盖原账本，保留原文件用于回退。「导出业务副本」为仅含业务的 JSON，不代替整库备份，尚无 JSON 恢复导入。

进程守护、磁盘权限和每日服务器内备份定时器已配置；仍需异地备份和恢复演练。当前为单进程 SQLite 架构；业务量增长前需容量测试、分页及数据模型迁移。iPhone 客户端共用后端，上线时须切换至可用的正式 HTTPS 地址。

原生部署的 `TRUST_PROXY_IP=127.0.0.1`，仅适用于受控主机内的 Caddy 直接面向客户端；本机进程均属于信任边界。Caddy 必须覆盖 `X-Finance-Client-IP`，不能公开 4318 或直接相信客户端的 `X-Forwarded-For`。仓库另保留使用独立容器网络的 Compose 方案，尚未用于本次部署。实际路径、命令与不同部署方式的信任边界见 [部署方案与费用](部署方案与费用.md)。

## 日利润与月利润（2026-10-17）

网页与 App 首页均保留月利润，并增加日利润切换。日利润按实际业务日期统计回款确认毛利、费用、退货冲回和运费调整，再扣日均税费。月报继续使用原来的手填月度税费，不叠加日报分摊值。

日均税费按当月实际天数分摊，整数分尾差依次分配到月初各日，整月合计恰好等于月税费。当前月份未登记税费时，参考上个月已登记税费，以当前月份天数分摊，显示“暂估”；登记本月金额后自动重算，明确登记零元也视为已有实际值。历史月使用该月实际登记金额，历史月未填写或当前月缺少上月参考时标注税费待补，不伪造依据。

`GET /api/workspace?month=YYYY-MM&date=YYYY-MM-DD` 同版本返回 `report`（月报）、`dailyReport`（日报）和 `date`；日报含 `taxEstimated`、`taxMissing`、`taxSourceMonth`、`monthlyTax`、`daysInMonth`。全部为只读计算，不增加流水、税费记录或数据库迁移。


## 2026-10-17 最新业务规则

- 期初建档：老板在空白账本建立账户、型号、客户、供应商，确认启用日期、全部余额、库存及期初未结销售。库存填写数量和单件到货成本，未结销售填写数量及整单原售价、总成本、运费与已回款。期初值不虚增本期利润。
- 不再提供串号管理、录入、扫描或搜索。保留旧记录用于审计兼容，不物理清除已售历史；后台成本记录不是新的串号档案。新采购、销售、退货都只需型号与数量。
- 移动加权平均：每次入库将该型号现存成本和新货采购价、进货运费合并；出库按总库存成本 × 出库数量 / 在库数量结转，按分取整并保留剩余库存价值。退货使用原销售成本回仓后重新平均。已售历史成本不被后续进货改写。同型号库存业务不允许倒序录入。
- 一次销售以整单金额、整单运费填写；系统保留成本分配记录，界面和对账单合并为型号、数量的一单。部分退货按原售价回仓，已确认利润在退货当期冲回，已发生的销售运费保留为损失。供应商分析仍依据采购来源分配，不能证明某件实物来源。
- 库存盘点：填写全部型号实盘数量（没有则填 0），记录盘盈盘亏并进入待办，不自动制造采购、销售或修改库存价值。
- 客户新建可选 0–365 天账期；销售时冻结账期。到期提醒和对账单使用实际账本。日报提醒北京时间 20:00，可在设备设置中调整。
- 流水更正/撤销：先预览账户、往来、老板垫款与利润影响。原记录和原因保留；后续业务不成立或影响已关账月份时拒绝更正。通知只在最终保存成功后生成。

## 财务操作通知与苹果推送

财务角色每次新增、更正或撤销业务成功后，为当时启用的所有老板账号各生成一条通知。通知与账本提交在同一 SQLite 事务内，幂等重试不重复生成。老板在网页「财务操作通知」或 App 首页/我的查看未读、操作人、业务日期、修改前后内容。只看预览、保存失败及老板自身操作不触发财务通知。

新服务启动时只新增独立的通知、设备及待发送队列表，不改写库存或流水。升级前按原备份流程备份整库。通知只能由对应老板读取和标记已读；财务不能查询通知中心。设备退出登录、成员被停用或密码被管理员重置时解除对应绑定。

系统推送尚未上线。配置步骤：

1. Apple Developer 会员激活后，在 App ID `com.luxinghe.yuantuofinance` 启用 Push Notifications，更新签名描述文件。工程已为 iPhone 真机设置 `Push.entitlements`，Debug 使用 development，Release/TestFlight 使用 production；模拟器不作为推送送达验收。
2. 由账号持有人生成 APNs `.p8` 密钥，保存至服务器受限目录，权限仅运行用户可读；不要放进 Git 或发送到聊天。配置 `APNS_KEY_PATH`（私钥文件路径）、`APNS_KEY_ID`、`APNS_TEAM_ID` 和 `APNS_TOPIC=com.luxinghe.yuantuofinance`。
3. 备案、正式 HTTPS 和服务器部署完成后，重启服务。四项配置全部缺省时仅提供 App 内通知；部分配置缺失时明确启动报错。
4. 真机以老板账号登录，允许系统通知并打开通知中心确认设备绑定。使用独立测试账本，财务从另一端新增、更正、撤销各一笔，检查前台、后台及锁屏通知，并确认点开后必须通过应用身份保护才能查看详情。
5. 待发送队列每 15 秒处理一批。APNs 接受后记为 sent（不等于设备必然展示）；暂时故障指数退避、最多 8 次。无效令牌停用，已读或超过 48 小时不补推。未知送达结果重试采用同一通知标识与折叠标识，极端网络情况下仍不能承诺系统通知绝对不重复。

锁屏只显示“财务已更新公司账本”，不发送账户余额、客户名称、金额或备注。推送设备令牌与随机安装标识仅用于绑定老板通知。日报与客户逾期为原有本地提醒，与操作远程推送分别处理。
