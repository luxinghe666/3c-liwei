# 首版功能与日常流程

整理日期：2026-10-15。依据《财务软件需求确认稿 v0.11》。这是便于讨论的页面与流程提案，尚未开发软件；页面名称及排布属于设计建议。

## 1. 老板和财务各自怎样使用

老板首页优先展示：6 个账户余额及汇总、本月已收款销售利润、本月公司利润、客户总欠款／可用余额、上游可用余额与未到货、公司欠老板金额。金额均可点开查明细，缺成本或待补信息会影响利润时明确提示。

财务在电脑上完成导入、补录运费、日常收付和往来核对。老板可用手机浏览器查看全部数据；未关账月份由财务更正，已关账月份由老板处理，修改保留前后记录。

## 2. 首版页面建议

| 页面 | 主要工作 | 避免重复录入的设计 |
|---|---|---|
| 经营首页 | 资金、利润、客户欠款、上游余额、老板往来与待处理事项 | 由业务记录汇总，首页不另外填一遍金额 |
| 资金流水 | 6 个账户收付、账户互转、老板垫入、直接代付、归还本金 | 内部转账一次填写生成两端关联；老板外部代付不虚构公司银行流水 |
| 上游与采购 | 供应商对账、锁货、发货、在途、到货、退款 | 到货关联锁货，已锁货金额不在入库时再扣上游余额 |
| 客户与销售 | 销售、退货、账单、回款和余额抵扣；保留市场价及报价加点 | 只登记客户回款总额，系统自动从早到晚分配；退货余额抵扣不新增银行回款 |
| 库存与串号 | 单台采购来源、成本、库存及销售／退货轨迹；配件数量和平均成本 | 串号表补关联，不重复生成日报已导入的采购或销售 |
| 费用与票据 | 公司日常费用、实际收票／开票明细、月度税费 | 进销运费在业务页面填；月结、实际付款与原费用关联 |
| 利润报表 | 已收款销售利润、部分回款、当月退货冲回、公司费用、月度税费 | 明细可追溯到销售、成本、回款分配及调整记录 |
| 导入与设置 | 博远文件导入、期初数据、基础资料、账号及数据导出 | 同一入口检查重复、来源版本、缺串号及金额差异 |

## 3. 财务每天的操作

### 上游付款、锁货和收货

1. 实际付款发生时登记资金流水，关联供应商；老板在外部直接代付则选择老板代付业务，记录欠老板金额。
2. 微信确认锁货后，财务登记供应商、商品、数量、约定价格及锁货时间；系统按已确认规则扣减上游可用余额。
3. 上游发货后补发货时间和物流信息，用于查看在途天数。
4. 导入或录入采购入库时，关联锁货和实际串号，在同一页面填写进货快递费，默认按数量分摊，可手工调整。
5. 收货更新库存及履约进度，不重复扣减锁货款。采购取消退款分别记录应退和实际到账，到账后才增加银行余额。

已收货退给供应商只在少量质量问题时发生。首版设计提案是保留关联原采购和串号的基础登记；退款、换新或冲抵上游余额按实际协商结果处理，当前尚未确认统一方式，也不能直接沿用取消未到货采购的退款流程。

### 销售、回款和退货

1. 导入或录入销售，绑定售出串号；无串号配件按同型号库存平均成本处理。
2. 在销售／出库页面填写销售快递费。带票报价保留市场价格和本次加点，实际发票明细另行手录。
3. 财务登记客户回款总额及实际收款账户，系统自动按销售日期从早到晚抵扣；回款覆盖多少，就按比例确认对应销售利润。
4. 客户退货按原销售价记入账单，关联原销售和串号。已确认利润在退货当月冲回，原月份报表保留；实际发生且不可退回的运费不能自动消失。
5. 退货留下的余额抵扣新销售时，按新货成本确认对应利润，不新增银行回款。

常见路径是客户退回我方。客户换货尚未单独确认，建议如需处理时关联“原货退回＋新货销售”，差额进入客户往来；是否采用及低频细节留在页面设计时核对。

### 账户和老板往来

| 业务 | 6 个账户的变化 | 公司欠老板的变化 | 利润处理 |
|---|---|---|---|
| 6 个账户内部互转 | 转出减少、转入增加，汇总本金不变 | 不变 | 转账本金不计收入或费用 |
| 老板从外部账户转入 | 实际收款账户增加 | 增加垫款本金 | 不直接计利润 |
| 老板在外部代付货款 | 不虚构公司银行流水 | 增加垫款本金 | 关联采购，按货物成本及销售规则处理 |
| 老板在外部代付公司日常费用 | 不虚构公司银行流水 | 增加垫款本金 | 按实际代付月份记公司经营费用 |
| 公司归还老板本金 | 实际付款账户减少 | 减少归还本金 | 不重复扣采购成本或费用 |

借款本金和利息分别记录；利息仍按用户确认的实际发生金额手工登记。

## 4. 每月的操作

1. 核对 6 个账户余额、客户往来和供应商往来，处理缺失或重复记录。
2. 使用快递账单核对已经登记的销售运费，只处理差额。已确认利润对应的差额在本月单列调整，保留原月份报表；支付月结账单不再把整份账单扣一次利润。部分回款对应的差额应拆清已确认和待确认部分，避免重复计入，具体分配方式在设计中完善。
3. 工资、房租、人情往来、利息等公司日常费用按实际付款月份扣减。采购、销售中已经登记的运费不重复算入公司日常费用。
4. 财务手录实际采购／销售发票明细，再按月份填写税费金额。税费扣减所选月份利润，首版不自动算税；实际缴税流水与已登记税费关联，避免重复扣减。
5. 查看缺成本、运费待补、税费待填及来源版本差异，完成必要核对。建议由老板关账；具体关账操作及提醒方式在页面设计时确定。

## 5. 首版应验证的结果

| 场景 | 应得到的结果 |
|---|---|
| 公司账户间转 10 万元 | 两个账户各有对应变动，6 个账户总资金与欠老板本金均不变 |
| 老板从外部转入 10 万元，再归还 2 万元 | 收付款可追溯，新增未归还本金 8 万元，不能计成 10 万元收入或 2 万元经营费用 |
| 老板外部直接代付 1000 元办公费 | 6 个账户无虚构流水，欠老板增加 1000 元，当月公司费用增加 1000 元；归还本金不再扣费用 |
| 10 台采购共 38 元进货运费 | 默认每台分摊 3.80 元，分摊总额仍为 38 元 |
| 一笔销售 3300 元、整单商品销售利润 100 元，只收到 1650 元 | 先确认利润 50 元；余款到账再确认剩余 50 元，账单与分配记录一致 |
| 已付清的销售退货 3300 元，客户后来再拿货 5000 元 | 退货产生余额 3300 元，新销售抵扣后欠款 1700 元；抵扣期间没有新的银行回款，新利润按新货成本计算 |
| 填写某月税费 2000 元，之后登记对应缴税付款 | 该月利润扣减合计 2000 元；付款更新账户，不再多扣 2000 元 |
| 上月已收款销售的运费原记 10 元，本月账单核实 12 元 | 本月单列运费调整并扣减利润 2 元；上月报表保留，月结付款不再扣一次原运费及差额 |
| 相同日报或串号文件再次导入 | 已有业务不重复增加，发生变化的记录显示具体差异 |
| 财务更正未关账记录／尝试更正已关账记录 | 前者按权限更正并留痕，后者交由老板处理 |

示例只验证用户确认的经营核算规则；完整成本、运费或期初信息缺失时应明确标识，不能按零成本填补。

## 6. 留待设计与实施准备的事项

- 低频业务：少量供应商质量退货的结果处理、客户换货补差及退货运费。基础登记与关联原单的方案属于设计提案，不因少见而直接视为已取消需求。
- 数据细节：同一串号多条采购来源的核对、销售批次运费分摊、部分回款销售的月结运费差额分配。已收款销售的补差归本月已确认，不再重复询问。
- 上线安排：启用日、历史未结销售及期初数据准备、部署位置与备份安排。
- 配件的具体平均成本算法及部分页面细节可结合原型提出建议，再统一确认。

跨月预收后发货的特殊利润归属已按用户要求暂不覆盖；普通客户预收余额和真实收付款仍保留记录。
